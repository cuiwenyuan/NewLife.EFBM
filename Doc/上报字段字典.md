# 上报字段字典（当前版本 · `ParseVersion=1.0`）

> 对应：[需求说明](../需求说明.md) §3.3 / §3.7 · [开发计划](../开发计划.md) P0 · [原始样例](../API上报接口数据示例.txt)
> 本文是**当前已知字段的冻结清单**，也是接收端解析器、`EventFieldRegistry`、字段监测页与《上报流接入说明》的共同数据源。按示例文件当前版本冻结后即可开工，不等待设备方后续字段清单。

## 1. 冻结口径

| 项 | 约定 |
| --- | --- |
| 数据来源 | `API上报接口数据示例.txt` 第 17 章的 6 类事件，以及需求说明 §3.3 的整理结果 |
| 解析版本 | `ParseVersion = 1.0`，随每条原始报文落库，用于判断该报文由哪一版解析器处理 |
| 版本递增 | 新增**已识别字段**、字段改名或正式列固化时递增小版本（1.1、1.2…）；仅出现未知字段不递增，未知字段走 `ExtJson` / `UnknownFields` |
| 冻结范围 | 只冻结「当前已知」字段，**不是字段白名单**：任何未列出的字段一律不拒绝、原样留存（需求说明 §3.5、§3.7） |
| 不冻结 | 设备端上报阈值、`status` 完整枚举、后续业务字段；这些变化不影响接口契约与 `EventKey` |

设备端失败不重发，因此本字典的任何变更都**不得**演变成「未登记字段即拒绝」。字典的用途是解析、展示、监测与固化，不是校验规则。

## 2. 通用信封

`POST /api/events`，`Content-Type: application/json; charset=utf-8`。

| 字段 | JSON 类型 | 必填 | 中文名 | 样例 | 处理 |
| --- | --- | :--: | --- | --- | --- |
| `event` | String | 是 | 事件类型 | `ORDER_COMPLETED` | 按字符串分发；未知值走兜底 handler，不拒绝 |
| `deviceId` | String | 是 | 设备编号 | `FBOX-A01` | 查凭据并校验绑定关系；首次上报可自动登记设备 |
| `timestamp` | String | 是 | 事件时间 | `2026-07-23T18:00:00+08:00` | ISO 8601 带时区偏移；**保留原始字符串**参与 `EventKey`，另解析为 UTC 用于排序 |
| `data` | Object | 否 | 业务载荷 | `{"orderId":"WO-..."}` | JSON 树承载，禁止强类型 DTO；`FAULT_CLEARED` 可无此字段 |

三项必填缺失或 JSON 无法解析 → 400 直接丢弃；其余一切情况正常入流。顶层出现未列出的字段同样原样留存并计入 `UnknownFields`。

### 2.1 接收端生成字段（不属于设备报文）

| 字段 | 类型 | 出现位置 | 说明 |
| --- | --- | --- | --- |
| `messageId` | String(UUID) | 响应、Stream 消息体、原始报文、死信、兜底 | 消息追踪，**不参与去重** |
| `eventKey` | String(SHA1 十六进制) | 响应、Stream 消息体、全部实体 | `SHA1(event|deviceId|timestamp)`，全链路唯一幂等键，**不含 `data`** |
| `rawJson` | String | Stream 消息体、`DeviceEventRaw` | 未经改写的原始报文全文 |
| `dataJson` | String | `DeviceEventRaw` | `data` 节点原文；无 `data` 时为空 |
| `receivedAt` | DateTime(UTC) | Stream 消息体、`DeviceEventRaw` | 服务端接收时间 |
| `sourceIp` | String | Stream 消息体、`DeviceEventRaw` | 来源 IP（经反代取 `X-Forwarded-For`） |
| `replayOf` | String | Stream 消息体（重放时） | 指向原 `messageId`，首次为空；外部系统据此识别重放 |
| `streamId` | String | `DeviceEventRaw`、`DeadLetter` | `XADD` 返回的消息 ID，消费时补记，用于定位与安全裁剪 |
| `extJson` | String | 原始报文与聚合表 | 未识别字段的 JSON，字段固化前的临时载体 |
| `unknownFields` | String | `DeviceEventRaw` | 未识别字段名清单（逗号分隔），供后台汇总 |
| `parseVersion` / `parseWarning` | String | `DeviceEventRaw`、聚合表 | 解析器版本与告警编码，见 §5 |
| `repeatCount` | Int32 | `DeviceEventRaw` | 同一 `EventKey` 重复投递次数 |

## 3. 事件与 `data` 字段矩阵

「必填」列指**业务上应当存在**；接收端一律不因缺失而拒绝，只打 `ParseWarning`（§5）。

| `event` | 中文名 | `data` 字段 | 说明 |
| --- | --- | --- | --- |
| `ORDER_STARTED` | 工单开始生产 | `orderId`, `boxId` | 建 / 更工单，写 `StartedAt` |
| `ORDER_PROGRESS` | 产量里程碑 | `orderId`, `boxId`, `planQty`, `completedQty` | 阈值由设备端控制，接收端不判断 |
| `ORDER_COMPLETED` | **逐件完成**（每折好一个盒子上报一次） | `orderId`, `boxId`, `planQty`, `completedQty` | `completedQty` 为**累计值**；每条写一条逐件明细 |
| `DEVICE_STATUS_CHANGED` | 设备状态切换 | `status` | 原值入库，不做枚举白名单 |
| `FAULT_OCCURRED` | 报错上报 | `message` | 新增故障记录 |
| `FAULT_CLEARED` | 故障清除 | 无 | 关闭最近一条未清除故障 |

### 3.1 `data` 字段明细

| 字段 | 中文名 | JSON 类型 | 适用事件 | 业务必填 | 样例 | 落库列 | 已固化 | 说明 |
| --- | --- | --- | --- | :--: | --- | --- | :--: | --- |
| `orderId` | 工单号 | String | `ORDER_STARTED` / `ORDER_PROGRESS` / `ORDER_COMPLETED` | 是 | `WO-20260723-001` | `WorkOrder.OrderId`、`ProductionRecord.OrderId` | 是 | 工单唯一键；同工单按此分区串行 |
| `boxId` | 盒型 / 盒号 | String | `ORDER_STARTED` / `ORDER_PROGRESS` / `ORDER_COMPLETED` | 是 | `BOX-0001` | `ProductionRecord.BoxId`、`WorkOrder.BoxId` | 是 | 样例未说明语义，按字符串原值保存，**不推断是盒型还是流水号** |
| `planQty` | 计划数量 | Number(Int32) | `ORDER_PROGRESS` / `ORDER_COMPLETED` | 是 | `1000` | `WorkOrder.PlanQty`、`ProductionRecord.PlanQty` | 是 | 工单完成状态由 `completedQty >= planQty` 派生 |
| `completedQty` | 累计完成数 | Number(Int32) | `ORDER_PROGRESS` / `ORDER_COMPLETED` | 是 | `1000` | `WorkOrder.CompletedQty`、`ProductionRecord.CompletedQty` | 是 | **累计值**，按取大收敛，禁止旧值覆盖新值 |
| `status` | 设备状态原值 | String | `DEVICE_STATUS_CHANGED` | 是 | `RUNNING` | `DeviceStatusLog.StatusRaw`、`Device.StatusRaw` | 是 | 不校验枚举；展示层查 `StatusDict`，未命中原样显示 |
| `message` | 故障信息 | String | `FAULT_OCCURRED` | 是 | `报错信息` | `FaultRecord.Message` | 是 | 长文本，不截断 |

> 6 个字段全部已固化（有正式列）。后续新增字段先落 `ExtJson`，需要查询 / 统计 / 索引时才按 §6 固化并回填历史。

### 3.2 `status` 展示字典（初版）

| 原值 | 中文名 | 备注 |
| --- | --- | --- |
| `IDLE` | 空闲 | 示例文件 17.2 给出 |
| `RUNNING` | 运行 | 示例文件 17.2 给出 |
| `PAUSED` | 暂停 | 示例文件 17.2 给出 |
| `FAULT` | 故障 | 示例文件 17.2 给出 |

示例的枚举以 `/` 结尾，疑似未列全（`OFFLINE` / `MAINTAIN` 等）。**不按此表校验**：未知状态原样入库，后期在后台「状态字典维护」页补映射即可；表格顺序即 `StatusDict` 初值。

## 4. 当前版本的合法报文样例

用于 P1/P2 的契约测试与联调基线。示例文件 17.2 的尾随逗号与空 `status` 是样例瑕疵（§7），此处给出合法版本。

```json
// ORDER_STARTED
{"event":"ORDER_STARTED","deviceId":"FBOX-A01","timestamp":"2026-07-23T18:00:00+08:00",
 "data":{"orderId":"WO-20260723-001","boxId":"BOX-0001"}}

// ORDER_PROGRESS
{"event":"ORDER_PROGRESS","deviceId":"FBOX-A01","timestamp":"2026-07-23T18:00:05+08:00",
 "data":{"orderId":"WO-20260723-001","boxId":"BOX-0001","planQty":1000,"completedQty":100}}

// ORDER_COMPLETED（逐件，completedQty 递增）
{"event":"ORDER_COMPLETED","deviceId":"FBOX-A01","timestamp":"2026-07-23T18:00:10+08:00",
 "data":{"orderId":"WO-20260723-001","boxId":"BOX-0001","planQty":1000,"completedQty":1}}

// DEVICE_STATUS_CHANGED
{"event":"DEVICE_STATUS_CHANGED","deviceId":"FBOX-A01","timestamp":"2026-07-23T18:00:15+08:00",
 "data":{"status":"RUNNING"}}

// FAULT_OCCURRED
{"event":"FAULT_OCCURRED","deviceId":"FBOX-A01","timestamp":"2026-07-23T18:00:20+08:00",
 "data":{"message":"报错信息"}}

// FAULT_CLEARED（无 data）
{"event":"FAULT_CLEARED","deviceId":"FBOX-A01","timestamp":"2026-07-23T18:00:25+08:00"}
```

`EventKey` 由 `event|deviceId|timestamp` 计算，与 `data` 完全无关：在 `ORDER_COMPLETED` 上追加 `boxType` / `operatorId` 等字段，键不变，幂等结果不变（验收用例 C16）。

## 5. `ParseWarning` 编码

告警只写入 `ParseWarning` 字段并供后台检索，**不影响响应码、不入死信、不阻断入流**。`EFBM.Core/EventEnvelopeParser.cs` 已实现下表全部编码；产出 `ExtJson` / `UnknownFields` / `ParseWarning` 供 P3 落库，**不写入 Stream 消息体**（消息体仍是 §2.1 的 9 个字段，外部消费组契约不变）。

| 编码 | 触发条件 | 接收端动作 |
| --- | --- | --- |
| `W100` | 某事件业务上应有的已识别字段缺失 | 缺省值继续处理，原文完整留存 |
| `W101` | 已识别字段类型不符（如 `planQty` 是字符串） | 尝试无损转换；失败按缺省值，原值留在 `RawJson` |
| `W102` | 出现未登记字段（含顶层字段、嵌套对象、数组） | 写入 `ExtJson` / `UnknownFields`，透传给所有消费组 |
| `W103` | 未知 `event` | 兜底 handler 只存原始报文并打标 |
| `W104` | 未知或空 `status` | 原值入库，展示字典未命中原样显示 |
| `W105` | `timestamp` 格式异常或无法转 UTC | 保留原始字符串，排序时间用 `receivedAt` 兜底 |
| `W106` | `data` 不是对象（数组 / 标量 / null） | 原文留存，`DataJson` 记原值，不解析子字段 |
| `W107` | 数量为负、超出 Int32 等数值异常 | 不拦截，原值留存，聚合时按取大收敛 |
| `W108` | 报文含重复 JSON 键 | 以解析器最后一次取值为准，原文不变 |

## 6. 字段演进流程

```
对方提供新字段 / 后台监测到未知字段
        ↓
登记到本字典（中文名、类型、所属事件、样例值、首次出现时间）
        ↓
判断是否需要查询 / 统计 / 索引
   ├─ 否 → 保持 ExtJson 承载，版本不变，数据不丢
   └─ 是 → ① Model.xml 加正式列 → ② xcode Model.xml 重新生成（.cs 覆盖、.Biz.cs 不覆盖）
             → ③ 部署 Migration=On 自动加列 → ④ 从 RawJson / DataJson 回溯回填历史，留回填记录
        ↓
ParseVersion 递增 → 更新 EventFieldRegistry → 回流需求说明 §3.7 与本字典
        ↓
更新《上报流接入说明》并通知外部消费组（按名取值、忽略未知字段）
```

**回溯回填是硬性步骤**：设备失败不重发，固化前的历史数据只能从全量原始报文补齐（FR-28、验收用例 C18）。每次固化必须记录时间范围、回填条数、失败条数与执行人。

## 7. 原始样例的已知瑕疵

| 位置 | 问题 | 本系统处理 |
| --- | --- | --- |
| 17.2 | `data` 中 `status: "",` 带尾随逗号，不是合法 JSON | 设备方需保证格式；接收端严格解析，无法解析即 400 丢弃（不重试、不猜测） |
| 17.2 | `status` 为空字符串 | 若合法报文传空值，原值入库并打 `W104`，不拒绝 |
| 17.4 | 「阈值待确认」注释混入 JSON 文本 | 阈值属设备端逻辑，接收端不判断，收到即记录 |
| 17.1 / 17.4 | 标题写「工单完成」，但注明每完成一件上报一次，`completedQty` 均为 1000 | 按用户确认：`ORDER_COMPLETED` 是**逐件完成**，`completedQty` 为累计值；事件名沿用对方报文不改 |
| 17.2 | 枚举以 `/` 结尾，疑似未列全 | 不校验枚举，后期在 `StatusDict` 补齐 |

## 8. 外部消费组约定

- Stream 消息体带 `rawJson` 原文，新字段自动透传；外部系统**按名取值、忽略未知字段、不得因未知字段报错**。
- 幂等以 `eventKey` 为准，重放消息带 `replayOf`；字段增减不改变 `eventKey`。
- 本字典是外部系统解析 `data` 的参考，不是强约束；以 `rawJson` 为准。
- 字段清单更新后，由运维同步《上报流接入说明》并通知各消费组；不要求设备端改动或停机。
